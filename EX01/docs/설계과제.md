## 파트 A. 지식 확인 (20점)

### A-1. 객관식 (각 2점, 10점)

1. Spring MVC 에서 사용자의 요청을 받아 흐름을 제어하고 뷰 이름을 반환하는 계층은?
   ① Controller  ② DAO  ③ DTO  ④ View

2. `@Autowired private MemberDAO memberDAO;` 가 동작하는 원리는?
   ① 상속  ② 의존성 주입(DI)  ③ 정적 호출  ④ 직렬화

3. `@Valid` 검증 결과(에러 목록)를 담아 컨트롤러로 전달하는 객체는?
   ① Model  ② BindingResult  ③ RedirectAttributes  ④ HttpSession

4. DAO 클래스에 붙여 영속 계층 빈으로 등록하는 스테레오타입 애너테이션은?
   ① `@Service`  ② `@Component`  ③ `@Repository`  ④ `@Controller`

5. 응집도 중 가장 바람직한(높은) 유형은?
   ① 우연적  ② 논리적  ③ 시간적  ④ 기능적

## 파트 B. 서술형 (30점)

### B-1. 공통 모듈 후보 식별 (12점)

이 프로젝트에서 **실제로 만든** 공통 컴포넌트를 기준으로, 공통 모듈 후보를 4개 이상
식별하고 각각이 왜 공통 모듈인지 한두 줄로 설명하라.

> 힌트: 한 도메인에 종속되지 않고 여러 기능/화면에서 반복 사용되는가? 를 기준으로 본다.
> 후보 예: `DataSourceConfig`(공통 DataSource), `GlobalExceptionHandler`(공통 예외 처리),
> DTO·DAO 패턴, Bean Validation 규칙(`@NotBlank`/`@Email`).

### B-2. 응집도·결합도 진단 (12점)

본 과제는 `Controller` 가 `Service` 없이 `DAO` 를 **직접 호출**한다.
(1) Controller / DAO / DTO 각각의 응집도와 결합도를 판정하고,
(2) Controller 가 DAO 를 직접 호출하는 구조의 장점과 한계를 서술하라.

### B-3. 명세 5원칙 (6점)

공통 모듈을 명세할 때 지켜야 할 5원칙(정확성·명확성·완전성·일관성·추적성)을 나열하고,
그중 2개를 골라 공통모듈 관리대장 작성에 어떻게 적용했는지 설명하라.
